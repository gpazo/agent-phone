# Design synthesis

The parent selected A. Scores for evidence, deadline, shared contract, ownership/API, and verification were A 5/5/5/4/4 and B 5/4/2/4/4. The independent Luna cross-judge returned the same scores and base. Both are one provider family, not cross-provider evidence.

A's flat all/any conditions express the real query-plus-result requirement on one observation. Its phone gate stays owned across the wait, preserving helper tokens until publication. B only supports OR and releases ownership between samples.

Graft B's last completed in-budget observation into failed timeout diagnostics. It is explicitly diagnostic and non-actionable. Keep timeout unsuccessful for CLI/MCP. Reject A's transient-error taxonomy and private startup goal. Only a valid unmatched sample repeats; malformed/protocol/helper errors return immediately. Matrix startup uses one context-bounded observation, with content readiness expressed by explicit wait steps. This reduces hidden retry policy.

The complete narrowed contract is implementation-task.md. Parent owns fixture, live verification, and documentation. Two workers implement that same contract in separate worktrees. Native builds and simulator operations remain serialized in the parent. A fresh code cross-judge will compare implementations after both finish.

Runtime revision: the first live run disproved the one-shot startup choice above. See code-synthesis.md for the accepted implementation and narrowly bounded readiness handling. This paragraph preserves the original design decision rather than presenting the later correction as the initial plan.
