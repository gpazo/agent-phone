## Shared public contract

`call wait` / MCP `phone_wait` accepts existing exact managed `device`, required `lease`, `conditions` (1..16), `mode` (`all` default or `any`), existing optional pointer `timeoutMs` (default30000, range1..30000), and `screenshot` (false default). Each condition is `{where:{...}, evidence:"tree"|"native-hit"}`. Selector fields are optional exact string equalities `role`, `label`, `identifier`, `value`, `context`, `action`. Distinguish omitted from empty strings using pointers. Require at least one field. No regex, numeric coercion, negation, stability knobs, or recursive expressions. `action` is membership in supported Element.Actions and requires native-hit evidence. Reject invalid roles/actions if enumerated. Native-hit is an AX center receipt, not pixel visibility. Explicit `visible` evidence must fail validation.

Success returns `WaitResult {observation, satisfied:[conditionIndexes], attempts, elapsedMs}`. All/any are evaluated against ONE sample. Timeout returns failed envelope code `wait_timeout` plus `WaitResult` diagnostics with `lastObservation` if any complete in-budget sample exists, `satisfied`, attempts, elapsedMs. Cancellation returns `cancelled`. Helper/protocol failures are terminal with partial diagnostics; do NOT retry arbitrary transport errors or add a new taxonomy of transient errors. Only an unsatisfied valid observation polls. LastObservation is diagnostic, never the current actionable observation. Do not publish intermediate/late samples. An attempt started by this wait invalidates the old current observation. Timeout before lock acquisition must not change phone state.

Matrix `action:"wait"` accepts the same fields and uses the same service method. A successful wait counts as a real assertion and updates current observation. Failure stores partial wait diagnostics in report and remains failed. Legacy `expect` keeps exact label-or-string-value tree presence and honest error wording. Replace the current broad startup retry with one context-bounded observe; do not invent a private first-sample goal/retry engine. Explicit wait steps own asynchronous content readiness. Retain existing invariants/reporting.

## Data shape and ownership

Name typed Condition/Selector/WaitResult values before logic. Use one typed validated wait query, one per-phone context-aware gate, and one sample then publish boundary. Prefer small focused wait.go/lock.go files to growing observation.go into a generic engine. Preserve zero-value-safe Phone construction used by tests and Service. Gate supports existing TryLock paths and context-aware admission; no goroutine blocked on sync.Mutex after caller returns. The wait budget begins at Service.Call entry before acquiring the gate; honor earlier parent deadlines and cancellation. Hold the phone gate during the bounded wait to keep lease/bridge/tokens single-owned. Validate and renew lease once at admission; check validity before samples/publication. Lease equality to expiry is expired.

Wait uses a fixed250ms interval after unmatched samples and interruptible timers. Deadline is a semantic acceptance cutoff, not a hard real-time delivery promise. Check actual monotonic time as well as ctx.Err before accepting sample and after optional screenshot/bookkeeping, so delayed context timer never accepts late success. OS cleanup/JSON/FS can delay error delivery but cannot produce success after cutoff.

Split capture from publication as needed, shared with observe. Add `Element.NativeHitAt *time.Time` as accepted receipt completion time. Preserve AX and screenshot times separately. Probe eligibility is distinct from input capability. Local complete unambiguous passive nodes may receive a native-hit receipt but never actions/tokens used for input. Native candidate association requires same raw identity, app, context, valid nonempty token. Incomplete, remote and ambiguous evidence stays unverified. Use ONE capture-targets batch per sample because each batch replaces native tokens. Prioritize native-hit query candidates, then ordinary actionable candidates. Deduplicate indexes. More than250 required probe candidates returns `selector_too_broad`; never silently starve a target. Tree-only queries do not probe all passive nodes. Unrelated changing labels must not prevent a requested match. Keep native source unchanged unless demonstrably necessary.

## Context and persistent transport

Thread context through phoneBridge.Tree/Action/NewBridge and ALL callers. Existing max I/O caps remain, clipped by request deadline. Startup dial/prepare and socket/pipe reads/writes must stop on cancellation, not only deadline. Synchronize operation-local cancellation callback completion before releasing ownership so it cannot close the next operation's stream. Canceled/failed I/O closes/discards bridge under phone ownership; no unread late reply can enter next call. Successful persistent helpers outlive request context; no request-lifetime CommandContext for helper processes. Context canceled while merely sleeping need not kill healthy helpers. No input retries.

CLI HTTP request uses caller context and signals. MCP request contexts are registered before worker scheduling, canceled by notifications/cancelled and EOF. Cap pending tool requests at8 and reject overflow without blocking input reader; protect live duplicateIDs, distinguish numeric/string IDs. Keep cancellation mechanics narrow. Expose strict nested schema with enums/bounds matching parser. Timeout CLI exits nonzero and MCP isError=true but retain diagnostics; nested success screenshot still attaches image.
