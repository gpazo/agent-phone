# Implementation contract

Implement continuous live vision end to end in your assigned isolated copy of agent-phone. User wants four simulator cards streaming and fast agent eyes without lease/action-reference interference. Parent alone owns live simulators/service; do not connect to them, run CLI list/call, run simulator commands, or launch the dashboard. Do not write the original repository. No nested delegation; own the artifact and its tests directly. Existing source is the baseline; do not rebuild unrelated parts.

Read original AGENTS.md, grounding.md, probe-results.md, design synthesis when available, and the pstack poteto-agent persona. Produce code plus RATIONALE.md describing organizing data structure, tradeoffs, validation, and changed files. Source prototype is `/Users/gp/src/agent-phone/.cache/live-vision-probe/live_vision_probe.m` with proven runtime selectors and compact framing; adapt it rather than rediscovering APIs. Private headers/research live in `.cache/live-vision-research` in the original repo. Preserve provenance/license in THIRD_PARTY.md and native/LICENSE.idb. No new runtime dependencies. No commits (unborn source repo).

Required shape: one shared latest-frame producer per subscribed managed phone, entirely independent of Phone.mu, control leases, Bridge, and Observation. Typed frame cursor {epoch, sequence}, frame metadata (device, source capturedAt before readback, dimensions, JPEG), and explicit lifecycle/freshness status. Keep only newest frame and wake waiters with replaceable notification, never queue frames for slow clients. Full timestamps and state must never present old bytes as a new live capture. Source sampling heartbeat may produce same image; wait means newer captured frame, not semantic UI change.

Native host helper `AgentPhoneVision`: adapt tested Objective-C persistent CoreSimulator IOSurface source, default at most 4 Hz, 402px width, quality .68. No per-frame processes/files. Accept exact UDID and resolve selected Xcode (parent can pass developer dir or helper honor DEVELOPER_DIR/xcode-select once). Canonicalize NSUUID/string; guard private proxy calls with @try, not respondsToSelector alone. Require primary class-0 surface, reject unknown device/non-Booted state, check state during sampling, fail on lost surface, no ambiguous fallback. Bound JPEG to 2 MiB, metadata 8KiB; validate dimensions and source record identity in Go. Source timestamp before readback, one encode/write in flight. Disable CI intermediate caching; use per-sample autorelease pools. Detect parent exit (stdin EOF or parent PID) so a killed daemon does not orphan capture. Avoid spinning on stdin/out failure. Shutdown is signal-responsive and Go forcibly kills unresponsive process within bound. Separate Makefile target for host helper. Prototype uses u32BE metadata length + JSON + u32BE JPEG length + JPEG; may retain framing.

Service: read-only `frame` and `wait_frame` RPCs dispatched after exact managed-ID lookup and BEFORE Phone.mu/expiry/lease validation. `frame` returns latest fresh image, starting capture and waiting bounded <=8s if none. `wait_frame` accepts afterEpoch, afterSequence, timeoutMs (bounded 1..30000), returns newer sequence or epoch, clear timeout status, source metadata and JPEG. No ownership needed, extended, or invalidated. Common persistent `SubscribeFrames` used by stream route and RPCs; at most four active producers, eight readers/device; idle producer teardown after short grace (e.g. 2s so repeated agent calls reuse it), remove or cap idle entries to keep memory bounded. Last-reader close, canceled request, service shutdown, failure/retry, explicit shutdown/reboot all stop native workers and wake waiters correctly. At most one worker/device even across teardown/reattach. Bounded reconnect with backoff while subscribed. Detect stalled source as stale/disconnected, not live. Retired epoch results cannot overwrite new generation. Service.Close cancels/joins captures outside registry/action locks.

Transport: persistent GET `/vision/stream?device=...` over existing local Unix socket, NDJSON snapshots (base64 JPEG) is sufficient and easier than MIME; bound write deadline, release subscriber on EOF/client cancellation. One latest snapshot per write, no event backlog. `agent-phone watch --device UDID` (or `watch UDID` if documented) connects once, copies bounded stream to stdout, exits promptly on broken stdout and signal, no per-frame HTTP/CLI subprocess. Expose `phone_frame`, `phone_wait_frame` MCP tools with image content and metadata text without duplicating base64 into text. Existing observe/screenshot functionality remains intact. API errors must be clear, input bounds enforced.

Dashboard: replace screenshot preview with per-visible-card persistent watch process. Subscribe only booted managed phones, stop on disappearance/state change/app termination; reconnect bounded if service restarts. Read/decode off main thread; newest-only main actor handoff so slow UI never accumulates. Show last image with honest Live / reconnecting / stale / offline state and capture age; metadata fleet polling stays separate. Stream publication cannot make previews vanish while Phone.mu busy. Retain original card design and Show in Simulator button. Background/minimized pause is desirable if straightforward.

Tests: meaningful Go race tests using injected fake producer for shared ownership, action/lease independence, cursor/new epoch, timeout/cancellation, slow reader convergence, limits, failed/stalled helper, teardown and reattach. Protocol malformed/oversized input tests. Tests must not invoke actual simulators. Existing make test required. You may run Go tests with `.tools/go/bin/go` (symlink available); native/Swift builds are parent-serialized, DO NOT run xcrun/clang/swiftc builds during candidate work. Parent will compile and live-test selected implementation. Explain any untested behavior explicitly. Update README API/behavior in candidate, parent writes measured validation report.
